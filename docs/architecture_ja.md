## 設計上の制約

teradataevsui は、Teradata Vector Store を使用するサーバーサイドレンダリング方式の FastAPI アプリケーションです。Teradata Python SDK はプロセス全体で共有されるコンテキストを使用するため、本アプリケーションは意図的に単一プロセスで動作します。`TeradataRuntimeManager` は対話操作とバックグラウンドの SDK 操作を直列化し、処理の前に選択された接続プロファイルを再アクティブ化します。FastAPI が管理するバックグラウンドランナーは、永続ジョブを一度に 1 件ずつ実行します。`WEB_CONCURRENCY` の増加は拒否され、データベース単位のアプリケーションロックによって、複数のサーバープロセスが同じランタイムデータベースを共有することも防止されます。

SQLite はアプリケーションのコントロールプレーンデータベースです。ID 情報、サーバーセッション、暗号化された接続プロファイル、暗号化された外部サービス認証情報、永続ジョブの状態、アーティファクトのメタデータ、および監査記録を保存します。ベクトルデータと BookRAG テーブルは Teradata に、大容量ドキュメントと生成されたアーティファクトはファイルシステムに保持されます。

## モジュール境界

| レイヤー | モジュール | 責務 |
|---|---|---|
| アプリケーション | `app/main.py`, `app/core/` | アプリケーションファクトリ、設定、セキュリティ、エラー処理、ランタイム分離 |
| デリバリー | `app/routers/`, `app/templates/`, `app/static/` | HTTP コントラクト、HTMX フラグメント、プレゼンテーション |
| ワークフロー | `app/workflows/` | 接続、作成、検索、削除のオーケストレーション |
| サービス | `app/services/` | BookRAG、マルチフォーマット処理、認証情報、ジョブ、アーティファクト |
| インテグレーション | `app/integrations/`, `app/teradata_runtime.py` | Teradata および Unstructured アダプター |
| 永続化 | `app/repositories/`, `app/db/` | SQLite リポジトリ、マイグレーション、オンラインバックアップ |
| バックグラウンドジョブ | `app/services/job_worker.py`, `app/services/workflow_jobs.py` | 永続実行、ハートビート、再起動時のリカバリ |

依存関係は内側を向きます。ルーターはワークフローまたはサービスを呼び出し、それらがリポジトリとインテグレーションアダプターを呼び出します。テンプレートが SQLite に直接アクセスすることはありません。シークレットはランタイム操作で必要になった場合にのみ復号され、パスワード入力欄へ再表示されることはありません。

## ランタイム状態

- 永続化対象：ユーザー、ロール、セッションハッシュ、データベース接続プロファイル、Unstructured 設定、ジョブ、アーティファクト、監査イベント。
- ブラウザーセッション単位：選択中の接続、接続済み／切断済み状態、現在のアップロード、フォーム値、チャット履歴。
- プロセス全体：アクティブな Teradata SDK コンテキストは 1 つです。対話操作とバックグラウンドランナーは 1 つのランタイムロックを共有します。ジョブは一度に 1 件ずつ実行され、Teradata 操作のたびにコンテキストをクリーンアップします。
- 外部：Teradata 内の Vector Store と BookRAG テーブル、および API 内で実行される Unstructured ワークフロー。

## 拡張ルール

1. スキーマ変更は必ず新しい連番付きマイグレーションとして追加し、適用済みのマイグレーションを書き換えないでください。
2. 新しい SQLite クエリはテンプレートや JavaScript ではなく、リポジトリに配置してください。
3. 外部 SDK の呼び出しはインテグレーションまたはサービス境界の背後に配置してください。
4. 生成ファイルは `ArtifactLifecycle` に登録してください。破壊的なクリーンアップは既定で無効のままにします。
5. Web リクエストを越えて存続する必要がある処理には永続ジョブを使用してください。FastAPI が単一のバックグラウンドランナーを所有し、HTTP ルートは検証、キューへの登録、進捗表示のみを行います。
6. Teradata の実行に分散環境でもコンテキストの安全性を保てる境界を設けるまでは、別のアプリケーションプロセスを追加しないでください。

## 永続ワークフローの境界

ドキュメント解析、JSON から CSV への生成、CSV テーブルのロード、および Vector Store の作成には、安定した JSON コマンドペイロードとブラウザーによるポーリングを使用します。ペイロードには接続プロファイル ID が含まれますが、パスワード、PAT、PEM の内容、外部 API キーは含まれません。バックグラウンドランナーは、ハンドラーが必要とする場合にのみ認証情報を復号します。キュー待ち／実行中／成功／失敗／キャンセルの状態と進捗は Web の再起動後も保持され、停止したままの実行中ジョブはアプリケーション起動時に復旧されます。

リカバリはジョブを再取得しますが、外部操作がトランザクションとして再開可能であることを保証するものでは**ありません**。中断された CSV ロードは、以前のローダーが停止したことを確認してから調査する必要があります。アプリケーションは破壊的な自動再試行を拒否します。対象テーブルの問題を解決した後、明示的に新しい実行を開始してください。監視タイムアウトが発生してもリモートの Vector Store 操作はキャンセルされません。その後の作成処理では、まず既存ストアを確認し、そのインデックスを検証します。

CSV ロードマニフェストは、選択された接続プロファイル ID と、シークレットではない対象フィンガープリント（ホスト、ユーザー名、UES URL）に関連付けられます。キャッシュされたロード成功結果は、別のプロファイル、または同じプロファイル上で対象が変更された場合には再利用できません。パスワード、PAT、PEM のローテーションだけでは無効になりません。この関連付けがない従来のロード記録は、データベースの同一性を証明できないため、調査したうえで明示的な新規実行に置き換える必要があります。アトミックなジョブ取得と古い試行のフェンシングが各ジョブを保護し、単一のアプリケーションランナーが同じ SDK コンテキストを複数ジョブから同時に操作することを防ぎます。
